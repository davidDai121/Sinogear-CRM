## 分工及边界

- Claude：gpt-sales-workflow / gpt-workflow-selection / gpt-prompt / gpt-followup 及针对性测试。提示词按当前需求选择报价与运费模块，输出精简、历史去重。

## 记忆方案

采用现有 contact_events 的独立 sales-preference.v1 事件。按 orgId/userId 读取，仅当前销售生效，跨设备读取；不修改共享模板信封，也不增加表。个人通用、客户、订单三级。每次修订和撤销均追加事件；原销售指令保留。迁移 0041 已实际应用：新增按 schema 限定的 owner 查询索引，使用 JSON 文本等值条件匹配索引。

确定性识别清晰的语气/长度/称呼/报价表达/提问习惯等子句；明确跨客户语义才归为个人通用，其他默认当前订单，明确“这个客户”归客户。数字价格、转述客户要求、单轮操作不自动永久化；未识别的原句仍是本单记录。不是通用语义分类器，也不会承诺理解任意指令。界面允许调整作用范围、撤销与恢复，不额外询问分类。

混合指令按子句处理，例如“以后回复简短，今天报四台”。当前指令优先于偏好；报价数字及来源不受风格偏好覆盖。

## 历史身份隔离

只对明确介绍另一客户且带不同国际电话号码的历史原句建立隔离；同一源对话该身份下的后续指导一并隔离，直到明确切回当前客户。单独出现货代/收货人号码、外国港口或早于绑定的日期不会触发。

隔离发生在读取层，原事件不删除、不自动转归其他人；UI 可以查看原记录和原因。José 三条真实存档作为离线核验依据。

## 验收目标

1. 风格指导保存一次后，新会话/刷新仍继承；订单/客户/个人层范围正确；撤销后不被旧原话自动复活。
2. 临时“四台”、费用、引用客户的话不变成全局偏好。
3. 正常完整报价仍只调用一次，金额由本地计算；缺项短答继续报价，既有运费有效期不被改写。
4. 普通回复省掉无关模块；报价场景保守加载。真实出站时间晚于核算且包含完整主总价，只作为可能已回复的裁剪信号，不写入正式发送状态；其他报价/改数/港口/任务信号仍可加载规程。
5. 档案 No change/缺字段不清空已有档案；完整中文译文仍可解析。
6. José 混杂历史在 prompt 中隔离；货代、合法跨境港口不误删。
7. 主聊天与跟进证据只在角色、消息及正文可对应时去重；证据校验保留。
8. 日志记录真实模型请求次数、累计输入输出字符和总耗时；字符不冒充 token，填入不冒充发送或未修改。
