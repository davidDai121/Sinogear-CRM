## 已看到的问题与待验证的解释

真实 Jaycee 案例中，客户已说明日常个人使用，并在比较中国 SUV。销售口述包含锐放、混动、约 23,000 美元和皮卡更划算。旧回复省略前三项，重复旧 R08 报价，又问用途；内部策略把销售这段当成不应外露的信息。

原用户 prompt 共 57,659 字符。老板指导只有约 256 字符，夹在重复知识、工作记忆、销售流程、运费、核价、语言和跟进要求之间。已确认 CRM 会把上一条销售消息中的旧报价关键词与末尾用途问句结合，误载约 1.4 万字符的运费及核价流程。

误触发及信息遗漏有直接证据；长度、位置、术语歧义各自造成多大影响仍待对照。不能归结为“skill 超过多少字就不好”，也不能据此认定必须升级模型。

## 双方一致的实施顺序（尚未执行）

1. **冻结并留基线。** 保留现有包、CRM 模板知识、输入和输出；固定账号、Chat High、资料快照和时间截点。先比较基线与候选组合，失败或原因不清再拆分测试位置、模块、术语，控制评测用量。
2. **完整保住业务事实。** 对齐原技能、CRM 批准知识和当前授权，做逐条事实清单，保留价格、配置、付款、保修、充电、代理、认证与费用范围。第一阶段给 R08 请求直接提供完整适用事实，先不依赖关键词按需隐藏。删减对象是重复或冲突的行为指令。出现事实差异按来源、日期和适用范围处理，不为压缩而改写业务口径。
3. **让当前要求主导表达。** 口述时保留车型、批准对客数字和原意；讨论时正常讨论，改稿时直接改稿，入口按钮不强制决定意图。有具体事实或费用矛盾就在内部指出并给替代稿，不能默默删除重点、偷偷改回旧价或照写明知错误的结论。无需每轮问候、赞美、总结或反问。
4. **用真实案例先验收好不好用。** 选 3–5 段有语境的真实案例做成对草稿，包括已有失败案例；从能确认是老板修改后采用的内容提炼少量表达习惯。没有这类证据的样本标为候选，不强行认定。先验证理解、事实与自然程度，再试点切换。
5. **验证 CRM 完整往返，再推广。** 保留三段输出、档案增量和必要跟进元数据；减少指导不能破坏功能。真实走 CRM 点击到正确技能、Chat High、上下文提交和自动回填。R08 通过后，将通用对话改法用于 Miles V2，各自业务资料保持独立。

## 八类验收

| 类别 | 通过条件 |
|---|---|
| 1. 本轮原意 | Jaycee 草稿保留锐放混动与约 23,000 美元；表达老板的比较意图。费用口径若有疑点在内部具体指出，不虚构精确节省、不悄悄删掉比较。不重复旧报价或已回答的用途问题。 |
| 2. 讨论与改稿 | “先跟我分析”得到中文讨论；“帮我改成一句”得到对应语言的一句正文和译文；两种输入框均按当前请求工作。 |
| 3. 事实完整且可用 | 七档价及范围全部核对，抽测付款、保修、充电、未知配置。汽油自动资料未确认不能说厂家没有。普通 Chat 独立读取 references 另测；未通过时不能宣称该入口已可靠。 |
| 4. 权威及冲突 | 客户声称新价不变成销售授权；老板本单明确特批按本单使用、不外推；同轮费用矛盾不掩盖、不静默改价，只处理真正依赖该信息的部分。 |
| 5. CRM 实际往返 | 正确客户、模板、技能身份、Chat High、本轮完整提交及自动回填都有可观察证据。缺少应有输出段、超时或取回失败不能用上一轮草稿冒充本轮完成；合法的内部讨论空段不当失败。 |
| 6. 档案和任务 | No change 不清档；内部讨论不误写客户事实；草稿不算已发送或已兑现承诺；跟进连续性和跨客户隔离保持。写入保护仅在离线环境或测试联系人验证，不在真实客户档案做试写。 |
| 7. 自然度 | 成对草稿先检查意图、是否答到问题、机械客套和多余提问，再给老板判断是否好用。少量案例是验收证据，不包装成统计胜率。此项须在正式切换前完成。 |
| 8. 成本和速度 | 不调用付费 API、不购买额度；保留 Chat High。记录点击到可用草稿的耗时、输入字符数和重试次数，样本数如实记录，不把字符当 token、不承诺不消耗任何账号额度。 |

所有线上评测只生成草稿，不点击发送客户消息。真实客户可用于只读分析；需要验证写入时使用测试联系人或离线环境。
