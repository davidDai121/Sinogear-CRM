### 3n. 去重收窄 + 契约改为标记二次跟进（2026-09-23 晚四，Codex 复核）
- 问题：3m 的去重把“本客户任何未完成且未来到期的任务”都当作覆盖，“周五准备 PI”“核对海运报价”会吞掉回访 → 丢线索。
- 改为 `sameNextStep`：模型准确引用 existingTaskId 优先；自动兜底只认可信匹配——标题核心互相包含、关键片段 Jaccard ≥ 0.5，或同一天到期且两边都是跟进 / 回访类标题；只看未完成、未来到期；拿不准保留新任务。测试：Jaycee 手工“二次跟进：询问 SUV/皮卡比较进度”覆盖（正例）；只有 PI / 海运任务时仍建回访（反例）；同一天两个跟进类算同一步；PI 同一天不算；笼统标题不同日期不算。
- 契约限制与修正：原契约“只选 primary next action”，模型会选 act“核对并发送本轮草稿”，二次跟进就没被标。现改为：发送本稿不是那个动作；普通回复要判断发出后是否需要二次跟进、什么时候（至少下一个工作日，按客户实际节奏、阶段和原话定），输出 review 带具体日期和业务依据；客户只是需要时间比较 / 决定仍是 review 带日期，不是 wait；act 只用于发稿以外的销售动作（PI、资料、老板确认）；wait 只用于有名字的外部条件并说明为何无法定日期。review 任务标题前缀改为“二次跟进：”。
- 仍有的限制（如实）：一轮只出一个决定。模型选 act（准备 PI 等）的那轮，二次跟进不会同时被标；模型判断 wait / stop 的轮次不建日期任务；模型不按规则输出时 CRM 只校验格式、时区、未来时间和证据引用，不替它选日期。“所有生成轮都标好了”不成立，只能说“普通回复轮契约要求标记二次跟进，落库有去重和人工保护”。效果等 CRM 端到端验收。

### 3o. 讨论后续聊生成被带偏：上一轮是讨论的会话不续用（2026-09-23 晚五，Codex CRM 实测）
- 现象：Jaycee 卡讨论“Right 是真认同还是礼貌附和？不要写客户回复，也不安排跟进”后，无指令点续聊生成，Chat High 收到完整三段 + 契约，却继续上一轮讨论，无三段、无 crm_followup；CRM 报“本轮未返回跟进判断”。同一 ChatGPT 会话里上一轮的“不要写客户回复”压过了本轮 prompt。
- 修法（最小）：`threadEndsWithDiscussion(entries, chatUrl)`——按 CRM 账本判定该会话最近一条草稿之前的输入是不是 sales_discussion；命中时生成不续该会话，改为带完整上下文（客户事实、本单记忆、最新草稿、契约）另起新会话，成功后 saveConversation 覆盖旧 URL，之后的生成 / 讨论都续新会话。生成后的讨论、讨论后的讨论照旧续用。不删任务、不发消息、不调 API。
- 补充（Codex 复核）：新会话的本单记忆仍带上一轮讨论原文“不要写客户回复，也不安排跟进”。两层渲染现在把 sales_discussion 单独列为 pastDiscussions（turnScoped:true），不再混在 ownerInstructions / salesHistory 里，头部写明其中的“不写客户消息 / 不安排跟进 / 先讨论”只对那一轮有效，本轮以当前请求和 CRM 输出契约为准；跟进契约的 note 也点名这些 owner 证据 id 不能决定本轮跟进。
- 再补（Codex 复核）：讨论 → 普通生成失败（同一旧 URL 存了无三段的草稿、没有 sales_instruction）→ 再次普通生成，原判定从最新草稿往前先碰到草稿就返回 false，会继续复用污染会话。判定改为两条：① 该会话最近一条草稿没有 [WhatsApp Reply] 三段标题即讨论态；② 往前扫时跳过同会话的无指令草稿，最近输入是 sales_discussion 即讨论态，遇到 sales_instruction 或别的会话的草稿停止。不用手工清会话。
