# 销售技能协同方案

日期：2026-09-17。

状态（2026-09-17更新）：4个本地业务技能已新增，R08线上规则已更新，CRM本单记忆已实测。按老板最新纠正，运费通过对话自行查3–5家公开来源、同口径取最高可比价估算；填写表单已撤销，不以固定货代为前置。客户判断回写、日历联动和六技能自动协同尚未完成。详见[客户记忆与运费实施](客户记忆与运费实施.md)。下文是整体目标，不表示全部上线。

2026-09-17补充：已用最近168小时的可读销售记录交叉核查本方案。逐组阅读146个客户记录的1,132条带日期CRM消息；134个GPT入口中84个可读，取得211轮并核查老板要求，50个入口仍有读取缺口。详见[本周证据与验收基线](../分析导出/销售技能一周验证_2026-09-17/需求与验收核查.md)。这些数字仅描述本次覆盖，不是整个账户全部聊天或技能通过率。

新增实施要求：保留本单老板授权及后续修订；一台/多台同时算总额、均价、节省与增购预算；区分估算和可执行运价；记录费用包含项防止重复计入装箱地面费；混装按本单装载依据；已报价但意向未知可问一次关键想法，明确等待则不催。报价参考、模型草稿和实际发送状态不可混用。客户身份、语言和历史角色质量是CRM自动写入的前提。

第一批验收采用用户贴出的上海→La Guaira原始运价作为费用拆分基准，库拉索EV本单授权作为多方案比较基准，Luis的公开参考拼接报价作为失败边界；原始金额不因此升级为通用当前运价。先冻结预期再改技能，数值准确和高风险错误为硬门槛，真实运价可用性、模型回放、保存重读、过期失效及CRM联调分别验收。

## 1. 用户要得到的结果

沿用CRM请ChatGPT帮助回复的入口，在同一次工作中形成客户正文和内部判断。客户当前问题能直接回答时及时回答；需要查运费、核价或了解当地竞争时才使用对应能力。

内部判断回答：这是哪笔需求、客户做了什么、目前卡在哪里、下一步由谁做、是否值得现在做、有没有必须记住的时间。CRM保存可靠结果并复用现有日历。普通消息不造成状态反复变化或待办堆积。

六类技能是业务分工，不要求用户开六个对话、重复传客户资料，也不预设每轮串行调用六个模型。技能总入口及运行环境接法需实际验证。

## 2. 业务技能清单与边界

| 类型 | 改动 | 输入与职责 | 输出与交接 |
| --- | --- | --- | --- |
| 单车型销售（首个为R08 Miles） | 修改现有 | 读本轮客户问题、真实历史、销售补充和适用的批准知识；组织回答与推进 | 客户正文、翻译、处理决定；供内部判断使用的新增事实；价格使用核算结果 |
| 运费查询 | 新增，优先 | 起运港、目的港、具体车辆动力/尺寸或物流所需条件、数量、日期；先查可复用记录，再补查 | 来源、费用范围、有效期、装载依据、整柜/滚装价格及单台分摊；无结果时保存缺项和询价草稿 |
| 成本核算与报价 | 新增 | 有适用范围的车价、运费、其他实际费用、汇率和本单批准规则 | 可重算的方案、报价范围、未知项目、总价与差额；引用输入记录版本，草稿/获批/已发送分开 |
| 当地市场调查 | 修改vehicle-export-audit | 客户提出当地更便宜、需要比较同款/竞品或销售明确要求调查 | 匹配年份/版本/税费/付款条件的当地价格记录及比较；普通询价不默认启动市场研究 |
| 客户判断 | 新增 | 同一需求的可靠事实、销售补充、历史判断、当前可行方案 | 投入建议、购买窗口、具体证据、卡点、缺项及下一步候选；不直接重写人工成交状态 |
| 跟进推进 | 新增 | 客户判断、双方已发生的承诺、真实发送状态、未结事项、人工安排 | 不提醒/等待条件/今日推荐/日历事项；给出负责人和理由，日历另需时间依据 |

R08是单车型技能的第一个实例，不把其他车型套成R08。其他车型已有模板和知识继续使用；通用的判断、运费、核算和跟进规则应可复用。后续新增车型技能另计实例数量。

关税/准入仅在明确需要时做专项核查，不作为运费和普通到港报价的前置步骤。到港报价说明当地税费和清关的范围；不因停止常规关税研究就把未知费用当零或承诺完税到手。

## 3. 每次回复的工作流程

1. CRM提供本轮可靠上下文、上一版判断、未结事项、人工安排及适用知识。销售补充的手机进展纳入上下文，标明来源；角色错标或多客户表单混杂时，不直接把该部分写入客户判断。
2. 单车型销售处理当前问题；客户判断作为同轮内部工作，不另要求销售发起一轮客户评估。已知问题不重复收集，不为了填满评估表而连问。
3. 缺当前报价所需运费才查询；有同条件且仍有效的记录先复用。需要数值方案时核算，明确请求或确有竞争问题时调查当地价格。普通参数问答不等待无关研究。
4. 汇总为一份客户草稿及内部卡片。缺少影响报价的关键数据时给出真实缺项或内部待确认内容，不能把待审数字当成批准报价。
5. CRM验证并保存内部结果，跟进规则决定是否更新原事项。生成/填入草稿不等于发送，写下“已查”“已保存”“已发”必须有对应结果。

若长查询需要分步处理，先保留已经核实的结果与查询状态，完成后针对关联需求补充；不得为此让普通问题反复重启全套研究。

## 4. 跟进规则：按用户最终要求

- 投入价值、购买意向、购买时间、今天是否要行动分别判断。客户有潜力可以等待；客户意向未知也不能漏掉我方已承诺的报价或资料。
- 根据具体采购动作与可解决障碍判断，不根据聊天长度、国籍、高报价、公司名或礼貌回应单独判优劣。
- 信息不足保留未知。手机记录缺失不等于没联系，缺预算不等于没钱，缺合适车源不等于客户差。
- 日历只放明确约定、我方承诺及有具体业务依据的一次性复核。已报价或两天未回本身不足以建任务。
- 今日推荐不设人数上限，允许零条；全部有价值机会保留并排序。未执行的推荐不自动变逾期，不每日累积。
- 等待条件可以没有日期。例如等合适车源、等付款条件成熟、等成本方案改善。一次复核无反馈不自动生成无限循环。
- 普通“OK/谢谢”、重复生成、无实质变化只更新必要事实，不新增任务、顺延日期或反复改阶段；关键新变化立即调整相关事项。
- 同一客户不同需求分别记录；核实为同一项目的私聊/群聊共享相关事项并保留负责人；不能按同车型/国家自动合并。
- 人工暂停、改期、成交/失败判断保留优先权，AI提示冲突，不静默改回。真正未完成的约定与逾期事项完整展示。
- 日历是“要办什么”，可能是我方核款、做PI或查运费，不都叫“联系客户”。

## 5. 记录与跨技能联动

每次新的查询或核算追加历史；复用已有记录时注明复用的记录ID及本轮适用性检查，不重复伪造一次新报价。结果保存来源链接、查询时间、报价/生效日期、有效期、适用范围、费用口径、已知项、未知项及假设。没有结果、资料冲突也保存。

记录分四组，避免混用：

- 运费记录：航线、货物/动力、数量、柜型/滚装、装载依据、币种、费用、承运条件及有效期。
- 市场记录：国家/当地市场、车型版本、新旧、挂牌或成交证据、税费及付款条件、查询来源。
- 报价记录：所引用车价/运费/汇率版本、本单授权、计算结果、草稿/批准/实际发送状态。
- 客户判断和行动：需求身份、证据范围、当前障碍、下一步负责人、等待条件、真实时间依据、人工决定。

例：某客户因当前运输成本缺乏优势而等待，后来同航线出现更好的有效运价。只有在该车型/数量仍适用、客户需求仍相关、新核算确实改善方案时，才建议重新联系。新运价不是群发指令，也不自动给所有同国客户建日历任务。已有承诺交付的报价遇到运费变动，则提示核查对应未结事项。

上述联动第一版可在打开客户、生成回复或完成查询时触发。定时后台监测、关机手机推送另行实施，不假设skill自身一直运行。

## 6. 必须配套的CRM工作

六类业务技能之外，需要实现以下系统能力；它们不另算六个skill：

1. **上下文和身份**：保证实际客户、销售、转发表单及旧AI草稿区分；只读历史回填先给差异建议，不批量把旧承诺变成今天逾期。
2. **入口和协议**：当前代码按一个技能身份绑定会话，R08及gpt-prompt.ts仍要求固定三段；不能仅新增技能文件就声称六技能自动联动。实现时验证单入口按需使用能力的接法，若环境不能调用依赖则使用明确的可执行替代或报缺项。
3. **内部结果隔离**：客户正文/翻译与判断、记录、计划分开；扩展协议与解析器一起改。NO_REPLY及ASK_BOSS不把内部处理提示当客户正文，格式异常不猜测写任务。
4. **持久化**：判断、查询、报价与任务分别保存；保留来源版本、客户和组织关联；重复抓取不重复创建，旧结果不覆盖新判断，失败明确显示。
5. **现有日历**：今日及逾期事项、独立今日推荐、等待条件、手动改期/完成/暂停、手机补记。按已有详细方案处理时区和计数，不以活跃度覆盖业务进度。

具体表结构、回写流程与验收沿用[客户判断与日历跟进方案](客户判断与日历跟进方案.md)。此前发现的代码问题来自样本核查，不在本轮声称已修复；实施前要核对当时源码和实际运行版本。

## 7. 实施顺序与验证

**第一批：运费→报价→R08。** 先把共同记录格式、判断/跟进输出边界纳入设计，选一条实际常用航线验证查询、费用范围、有效期、核算与草稿衔接。运费服务按调研选候选，真实可用性优先于宣传工具数量；仅使用文档已有或实际验证的能力。

**第二批：客户判断→跟进→CRM日历。** 接入前先处理影响自动写入的身份、内部正文隔离和阶段覆盖问题。使用已核查样本做只读回放，通过后在测试号验证保存、去重、人工覆盖和发送状态；再按授权范围启用真实数据。

**第三批：当地价格调查和新方案唤回。** 在有明确比较需求时接入，形成可复用市场记录；运费改善等事件能关联等待客户，但不制造普遍定时催办。
