# 下一步由谁做

先读当前需求、最近真实发送记录、未结任务、人工暂停/改期及客户时间表。AI生成或填入草稿不等于已发送，不能据此启动催办计时。先答仍未解决的客户问题。

- 已报价：结合本次采购背景和决定点，区分我方待答/交付、需调整方案、客户待决定或已问待答。优先解决会阻碍当前推进的我方事项；只对答案会改变下一步、尚未问过的未知问一个易答问题，可随实质答复自然提出，不为增加互动而追问。
- 近期已问待答：给客户合理回应窗口，不短时间换措辞连催；明确约定时间未到、客户明确拒绝联系、人工暂停时尊重安排。
- 隔了很久的客户：重新看最近实际发送、最后实质回复及已发生的未回应联系次数。过去泛泛说“忙/再考虑/到时候联系你”不能永久冻结跟进。已有真实需求或关系基础，隔了几周乃至两个月且没有当前禁联或未到的约定，通常应主动给出一条自然、具体、低压力的重新联系稿，确认计划或近况是否改变。这个确认本身有价值，不以新车源、新优惠、新运价或客户先来新消息为前提；也不必反复道歉。熟悉客户可以正常维护关系，不要求当下已有采购时间。例子不是固定天数阈值。
- 二次、三次跟进以实际发送和客户反馈计数，内部复核、未发草稿不算已经催过。多次实际联系无回应时降低频率、调整角度；不因模型复核过两次就停止经营客户。选择继续等待必须说明现在仍成立的理由，不能只引用几个月前一句“会联系”。客户已回复时先解决最新问题，不重复旧的唤回问句。
- 要PI、资料、运费或我方承诺核款：待办是我方交付，不退回泛泛“联系客户”；交付确需客户补资料时直接问必要缺项。本单明确、仍适用且无实质冲突的人工完成确认可作为依据，不因附件不可读而反复索证。
- 等新车源、可行运输方案、条件成熟：记录等待条件，可以没有日期。
- GPT负责判断是否跟进、下一步内容和何时复核。客户明确约定及老板安排优先；没有指定日期时，可以依据本单决策进度、最近实际发送、待交付事项、客户节奏及报价有效期，自主选择有理由的复核时间，明确标为AI判断，不冒充客户约定。确实只有等待条件而无合理日期时保留无日期等待，不机械套固定天数。
- 到复核时间先读取新增消息、任务状态与人工改期，再决定联系、交付、继续等待或结束跟进。定时复核不是定时发客户消息；老板本轮只授权GPT作判断和安排，不据此自动发送WhatsApp。复核本身也不触发无关运费重查。

今日值得做的全部保留并排序，不设人数上限，允许零条。未执行的建议不自动逾期、不每天累积。一次复核无反馈不自动无限循环。

推进内容应增加客户做决定所需的东西，例如可比较的方案、相关资料或已确认的交付进展，并说明它解决了客户哪项顾虑。报价理由已被客户否定时，不重复辩护，转向可兑现的条件或取舍；不擅自让价。按客户反馈展开信息，详细要求完整答，闲聊后自然回到相关决定，不把每轮聊天都变成催单。

写任务前先查同客户/需求/动作的未结事项；更新现有项而非重复创建，保留人工暂停、负责人和明确改期。跨项目不按相似标题合并；没有相关变化不重复重写计划，但实质经过的联系间隔属于重新评估的时间依据，不要求客户先发新消息。自动化执行范围以用户授权和现有工具为准；未实际保存不说已建任务，未发送不说已通知客户。

内部结果记录：行动/等待、理由和证据、负责人、关联需求/原任务ID、时间及其来源（未知留空）、完成条件。有新运价时先验证适用性并重算，只有方案改善且需求仍相关才建议唤回，不群发。

当前产品范围：优先接入GPT日常入口；Claude已取消，Gemini的共同记忆及跟进功能以后再上线。本机后台GPT复核默认关闭，用户2026-09-20要求避免未点生成时自行启动；日常判断和已有任务保留，不因更新skill或保存任务擅自开启后台。到期任务不等于获准调用GPT或发送客户消息。不把本地skill更新声称为CRM链路已部署。

CRM接入说明（2026-09-17）：GPT对话通过专用内部crm_followup块保存主要下一步，必须引用当前证据账本的真实ID和原文，记录人工/客户/GPT的时间来源。每个客户需求使用固定任务ID，重复讨论更新该任务；人工任务只可引用，不自动接管。不要把JSON放进WhatsApp正文。后台仅复核当前登录用户已经建立的GPT任务，依赖Chrome在线和已同步消息；首次使用不是对全部历史客户启动定时任务。手动日期、标题、关闭、删除及暂停保留，手动接管后不因模型输出撤销。实际保存回执和任务回读才代表完成安排。
